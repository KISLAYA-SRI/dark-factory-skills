# Dimension 4: Coverage (Unit Test Coverage) — Node/React Fix Patterns & Examples

## Overview

SonarQube measures **line coverage** and **branch coverage**, sourced from a coverage report (typically LCOV) generated by the project's test runner (Jest, Vitest, Mocha+nyc). The quality gate typically requires 80%+ overall coverage. New code often requires higher thresholds (e.g., 85% on new code).

---

## Identifying Uncovered Code from SonarQube

1. In SonarQube UI → Project → **Coverage** tab.
2. Click on a file to see line-by-line coverage (green = covered, red = uncovered).
3. Branch coverage shows uncovered `if/else`, ternary, and short-circuit branches.
4. Use the Sonar MCP tools to retrieve uncovered lines programmatically:
   - Call the discovered **Component Measures** tool with `metricKeys=coverage,uncovered_lines,uncovered_conditions` for overall project coverage.
   - Call the discovered **Coverage by File** tool to find files with the lowest coverage.
   - Call the discovered **File Coverage Detail** tool with the specific file component key for line-by-line and branch coverage details.

## Producing LCOV Coverage for SonarQube

SonarQube's JS/TS analyzer reads coverage from an LCOV file. Configure the test runner to emit one and point Sonar at it.

```jsonc
// package.json (Jest)
{
  "scripts": {
    "test": "jest",
    "test:coverage": "jest --coverage --coverageReporters=lcov --coverageReporters=text"
  },
  "jest": {
    "coverageDirectory": "coverage",
    "collectCoverageFrom": [
      "src/**/*.{ts,tsx,js,jsx}",
      "!src/**/*.d.ts",
      "!src/**/index.ts",
      "!src/**/*.stories.tsx"
    ],
    "coverageThreshold": {
      "global": {
        "lines": 80,
        "branches": 75,
        "functions": 80,
        "statements": 80
      }
    }
  }
}
```

```properties
# sonar-project.properties
sonar.javascript.lcov.reportPaths=coverage/lcov.info
sonar.typescript.lcov.reportPaths=coverage/lcov.info
sonar.testExecutionReportPaths=coverage/test-report.xml
sonar.coverage.exclusions=**/*.stories.tsx,**/*.d.ts,**/mocks/**,**/*.config.ts
```

For Vitest, use `@vitest/coverage-v8` (or `-istanbul`) with `reporter: ['lcov', 'text']` in `vitest.config.ts`, and point `sonar.javascript.lcov.reportPaths` at the generated `coverage/lcov.info`.

## Writing Unit Tests — Jest/Vitest for Node Services

```ts
import { describe, it, expect, vi, beforeEach } from 'vitest'; // or from '@jest/globals'
import { UserService } from './user.service';

describe('UserService', () => {
  let userRepository: { findById: ReturnType<typeof vi.fn> };
  let userService: UserService;

  beforeEach(() => {
    userRepository = { findById: vi.fn() };
    userService = new UserService(userRepository as any);
  });

  it('returns the user DTO when the user exists', async () => {
    userRepository.findById.mockResolvedValue({ id: '1', name: 'Alice' });

    const result = await userService.getUserById('1');

    expect(result).toEqual({ id: '1', name: 'Alice' });
    expect(userRepository.findById).toHaveBeenCalledWith('1');
  });

  it('throws NotFoundError when the user does not exist', async () => {
    userRepository.findById.mockResolvedValue(null);

    await expect(userService.getUserById('99')).rejects.toThrow('User not found: 99');
  });

  it('covers both branches of conditional logic', () => {
    expect(userService.canLogin({ status: 'ACTIVE' } as any)).toBe(true);
    expect(userService.canLogin({ status: 'INACTIVE' } as any)).toBe(false);
  });
});
```

## Testing React Components — React Testing Library

```tsx
import { render, screen, fireEvent, waitFor } from '@testing-library/react';
import userEvent from '@testing-library/user-event';
import { describe, it, expect, vi } from 'vitest';
import { UserForm } from './UserForm';

describe('UserForm', () => {
  it('renders validation error when the name is empty', async () => {
    render(<UserForm onSubmit={vi.fn()} />);

    await userEvent.click(screen.getByRole('button', { name: /submit/i }));

    expect(await screen.findByText(/name is required/i)).toBeInTheDocument();
  });

  it('calls onSubmit with the entered values', async () => {
    const handleSubmit = vi.fn();
    render(<UserForm onSubmit={handleSubmit} />);

    await userEvent.type(screen.getByLabelText(/name/i), 'Alice');
    await userEvent.click(screen.getByRole('button', { name: /submit/i }));

    await waitFor(() => {
      expect(handleSubmit).toHaveBeenCalledWith({ name: 'Alice' });
    });
  });
});
```

## Mocking HTTP Calls (fetch/axios)

```ts
import { vi } from 'vitest';
import axios from 'axios';

vi.mock('axios');
const mockedAxios = axios as unknown as { get: ReturnType<typeof vi.fn> };

it('returns order data on success', async () => {
  mockedAxios.get.mockResolvedValueOnce({ data: { id: '1' } });

  const order = await fetchOrder('1');

  expect(order).toEqual({ id: '1' });
});

it('throws a translated error on failure', async () => {
  mockedAxios.get.mockRejectedValueOnce(new Error('network error'));

  await expect(fetchOrder('1')).rejects.toThrow('Failed to fetch order 1');
});
```

For global `fetch`, use `msw` (Mock Service Worker) to intercept requests at the network layer instead of mocking the client directly, when the project already uses it.

## Coverage Strategy for Uncovered Lines

1. **Identify uncovered lines**: use SonarQube UI or the local HTML coverage report (`coverage/lcov-report/index.html`).
2. **Prioritize by risk**: service/business logic > API route handlers/controllers > presentational components.
3. **Cover all branches**: for each `if/else`, ternary, and `&&`/`||` short-circuit, write at least one test per branch.
4. **Error paths**: write tests that trigger each `catch` block, rejected promise, and thrown error.
5. **Null/empty inputs**: test with `null`, `undefined`, empty strings, empty arrays.
6. **Edge cases**: test boundary values (0, negative numbers, empty string, very long input).

---

## Coverage Thresholds by Layer

| Layer | Recommended Coverage |
|---|---|
| Service/business logic (Node) | 90%+ |
| API route handlers/controllers | 80%+ |
| React components (logic-bearing) | 80%+ |
| Custom hooks | 85%+ |
| Presentational/UI-only components | 60–70% (interaction-focused tests) |
| Generated code, type declarations, stories | Exclude |
| Configuration files | Exclude |
